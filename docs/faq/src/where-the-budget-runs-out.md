# Where a process's slot budget runs out

A process holds its capabilities in one table. The root has {{ROOT_ENTRIES}} entries (`ROOT_ENTRIES` in `kernel/verified/capability/table.rs`) and each leaf has {{LEAF_SLOTS}} slots, one fewer than the nodes on its page (`NODES_PER_PAGE` in `kernel/verified/capability/list.rs`), because the leaf's first node is its hidden node. A full table holds {{TABLE_SLOTS:,}} slots. The table starts with no leaf: the slots appear when a leaf is retyped, and no capability names the table. `design/process-holds-capabilities/`.

The limit binds when those slots are spent one to a piece of memory. A memory capability names one aligned block whose page count is a power of two, the power being the capability's order (`block_bytes` and `payload_wf` in `kernel/verified/capability/table.rs`). `design/capability-names-a-block/`.

A frame of one page is {{PAGE_SZ:,}} bytes (`PAGE_SZ` in `kernel/verified/define.rs`). `can_retype_frame` in `kernel/verified/capability/retype.rs` allows it, and the `RETYPE_FRAME` arm of `allows_retype` in `kernel/verified/capability/operation.rs` is how a caller asks for it. A frame of {{SIZE_2M:,}} bytes has order {{INDEX_BITS}} (`SIZE_2M` and `INDEX_BITS` in `kernel/verified/define.rs`). The `RETYPE_LARGE_FRAME` arm passes that order to `can_retype_large`, and the source writes the order as a literal. One slot per page over a full table reaches {{REACH_4K:,}} bytes. One slot per frame of {{SIZE_2M:,}} bytes reaches {{REACH_2M:,}} bytes. Each reach is the smaller of the table's slots times the block and the address space (`NODE_SPACE` in `kernel/verified/capability/list.rs`).

A block of {{SIZE_1G:,}} bytes has order {{ONE_G_ORDER}}, twice `INDEX_BITS` (`SIZE_1G` in `kernel/verified/define.rs`). `can_retype_large` allows order {{INDEX_BITS}} or order {{ONE_G_ORDER}}, and the source writes both as literals. `can_free_frame` in `kernel/verified/capability/operation.rs` accepts both. `allows_retype` passes only order {{INDEX_BITS}}, so a caller cannot retype the larger block. `design/capability-names-a-block/` leaves a frame of that size until the page table maps one, and `design/syscall-abi-in-registers/` records that retype accepts no kind for it. The plot still draws the line. One slot per block of {{SIZE_1G:,}} bytes would reach {{REACH_1G:,}} bytes, again the smaller of the table times the block and the address space.

An untyped takes any order up to `MAX_ORDER`, {{MAX_ORDER}} (`kernel/verified/capability/table.rs`). A block of that order is the address space: {{NODE_SPACE:,}} bytes, `NODE_SPACE` in `kernel/verified/capability/list.rs`, the end of the {{ADDRESS_BITS}}-bit space, and the same number as one page shifted left by `MAX_ORDER`. One such slot, based at the start of the space, covers it. A run lying inside the pages the block table tracks, decomposed at `MAX_ORDER`, has at most {{BLOCKS_PER_RUN}} blocks (`lemma_run_blocks` in `kernel/verified/capability/decompose.rs`). That is fewer than the table's {{TABLE_SLOTS:,}} slots. `design/untyped-memory/` and `design/root-process-at-boot/`.

![Slots one process needs against the memory it holds. Both axes are logarithmic.](./slots-versus-memory.svg)

The diagonals are one capability per block of one size: the slots are the memory divided by the block. The upper horizontal line is the full table, {{TABLE_SLOTS:,}} slots, and the dot on a diagonal is where that size reaches the table, or the address space when that comes first. The lower horizontal line is one run as untyped blocks, at most {{BLOCKS_PER_RUN}}. The vertical line is the address space, {{NODE_SPACE:,}} bytes. To the right of a dot that sits on the table's line, that process cannot hold the memory as separate blocks of that size. A larger block that retype does make, or an untyped block, still covers it, and one run stays within the untyped bound.
