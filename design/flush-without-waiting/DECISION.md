# Flushing without waiting under the lock

## Decision

A ghost per-core TLB model holds possibly stale translations, keyed by space and core, including the paging-structure caches for table pages. A space's translations enter it when a core loads that space. Unmap marks them stale. The model is a `TlbModel` the kernel value holds, one set of entries per core and one set of the tags, PCIDs or ASIDs, the core may hold entries under: proof code may add entries, since a model that holds more claims less, `load_translation_root` adds the tag it writes to the core's tags, and only the cited flush leaf, `flush_every_context`, empties a core's sets, so the prover keeps a core's model from being cleared without a flush of that core. Every tag a core may hold entries under is one it has handed out at its generation, so a new generation, which hands the PCIDs out again from the start, needs the core's flush first. The IOMMUs' model is an `IotlbModel` of the same shape, one set per IOMMU, which only `invalidate_iommu_all` empties, through its cited leaf `submit_invalidate`. Each cited leaf, like every other claim the proof takes on trust, is listed on `tools/external-body-list`, and the gate keeps that list whole: `tools/check-external-body.py` matches every `external_body`, `exec_allows_no_decreases_clause` and `assume_specification` in a crate marked verified against it, an assumed specification citing passages of documents `tools/hardware-documents` lists and lying in an arch module, and refuses an exemption from the proof written any other way; what the check is and is not claimed to catch is `design/committer-is-not-the-adversary/`. So what that list holds is all the prover takes on trust; what its items' callers owe, below, no step of the gate checks. The prover keeps verified code from making a token: `TlbModel`, `IotlbModel` and `BaseRegister` have fields private to the arch module, `design/arch-module/`. No token is `Copy` or `Clone`, and a tracked token is used once. So a core has one `BaseRegister`, and its own cannot be kept across a later write and put back in place of the one that write left. The unverified kernel in `kernel/src`, which makes other tracked values with `Tracked::assume_new`, makes the cores' `BaseRegister`s once, at boot, for the root and tag each core boots on, and the `TlbModel` and the `IotlbModel` once, at boot, with every set empty, a core's tags among them. Those are the models `CapKernel` holds. The flush IPI's handler in `kernel/src/flush.rs` first serves the boot test's flush state outside `CapKernel`, which runs before `CapKernel` is built: it makes a `TlbModel` of its own on each IPI, hands it to `flush_every_context` and drops it, so no model `CapKernel` holds is made there. It then acknowledges in `CapKernel`, when its core is behind the epoch. A core's acknowledgement makes its own flush: `CapKernel::acknowledge` reads the epoch and calls `flush_every_context` on the core's sets of the model in one step, so no register load or user code comes between the flush and what it clears, and the epoch acknowledged is the one read before the flush. That the flush runs on the core whose sets it empties is owed by the caller of `acknowledge`, which passes the core it runs on. Its callers on the running kernel are the flush IPI's handler and `CapKernel::enter`, the verified entry for every operation, which `dispatch` in `kernel/src/capability.rs` calls; the handler and `dispatch` each pass `cpu::get_cpu_id()`. The same holds for `switch_space`: `load_translation_root` writes the register of the core it runs on, whatever core it is given, so the record `switch_space` writes is that core's only when its caller passes the core it runs on. The caller owes it: today's one caller is the boot in `kernel/src/capability.rs`, which runs on CPU 0 and passes 0, and the handler in `kernel/src/flush.rs` passes `cpu::get_cpu_id()` to `flush_every_context` the same way. When a core switches spaces, and the one operation that does it, is `design/core-names-a-space-while-running-its-thread/`. Each core's state also records the space its page-table base register names, written only by `switch_space`, which writes the register itself through the core's `BaseRegister` and `load_translation_root`, verified code over the cited leaves `read_cr4` and `write_cr3` on x86_64 and `write_ttbr0` on aarch64, so the record is the register's latest write, and only for a space the core has loaded that is not retired, so a core's acknowledgement of a space's retire is not undone by the core walking that space again. The write's tag is `tag_written`: the id the space holds on the core, which the space keeps while the register names it, on a core that tags its TLB entries (`tags_tlb`: every aarch64 core, and an x86_64 core with CR4.PCIDE set), and 0, `KERNEL_TAG`, on one that does not. The model keys its entries by space and core, not by tag, so the acknowledgement's meaning does not rest on the tag, and a core that does not tag its TLB drops its entries for user pages at each write of the register. That CR4.PCIDE is fixed on each x86_64 core while verified code runs is glue's: the loader and the AP trampoline in `machine/pc` set it before verified code runs, and the kernel writes CR4 only to set bits or to toggle PGE; `design/teardown-driven-by-retype/` names each. A register naming no space is written under `KERNEL_TAG`, which no space holds, at the kernel's own root, which the model keeps and boot hands to no block, so no space can have it; what the glue still owes is the boot write that puts that root in each core's register and that the root maps nothing of a space; `design/teardown-driven-by-retype/`.

Storage is bounded: one flush epoch, one acknowledged epoch per core in the per-CPU list, and one stale epoch per block, the word at the block's level, so an unmap writes the 4K, 2M and 1G words for its page and a free reads its block's one. The comparison is strict: unmap bumps the epoch first and records the new value, and retype requires the acknowledgement of every core a free waits for to have reached it. The handler's flush covers all PCIDs, since a flush of the current one would leave stale entries under others and its acknowledgement would then mean nothing.

The kernel never waits for another core while holding the lock. A flush bumps the epoch, sends IPIs and returns `again`. The IPIs go to the unmapped space's list of cores, exactly the cores that have loaded it. Only those may hold an entry of the space in the model, so a core that never loaded it, such as an isolated core of another partition, is never sent one; `flush_sent` in `kernel/verified/capability/unmap.rs` states it. A core stays on the list once on it, and of the cores on it only those that depend on the space may hold an entry: a core on the list of a dead process's space that a retype retired since the core last loaded it no longer depends on it once its acknowledgement reaches the retire epoch, since the retire ran while no core's base register named the space and none can name it again until a load clears the retire, `design/teardown-driven-by-retype/`. The target's handler, entering the kernel as any entry does, flushes and records its acknowledgement in that one step under the lock, so all of this stays inside the `Kernel` value. Each kind of address space has its own flush with the same token: IPI for a process table, IOTLB invalidate for a device space, kick plus TLB_CONTROL for a nested table, `design/vmm-over-svm/`.

An IOMMU is acknowledged inside the step that invalidates it. The arch module's `invalidate_iommu_all`, verified code over the cited hardware leaves `read_head` (`read_producer` on aarch64), `store_command` and `submit_invalidate` (`design/arch-module/`, item 6), stores an invalidate of all the IOMMU's caches and a command that completes after it in the IOMMU's command ring, where the IOMMU fetches next (INVALIDATE_IOMMU_ALL and COMPLETION_WAIT on AMD-Vi, CMD_CFGI_ALL, CMD_TLBI_NSNH_ALL and CMD_SYNC on SMMUv3); `submit_invalidate` moves the tail past them and spins until the IOMMU shows the last one done; then it empties the IOMMU's set of the `IotlbModel`: the lock is held throughout, so no table changes during the wait, and once the invalidate is done the IOMMU holds nothing the tables no longer say. `flush_iommu` reads the epoch, makes the invalidate and records the epoch as the IOMMU's acknowledgement in one step, so no unmap comes between the invalidate and the epoch it acknowledges, and no caller names the epoch.

The calling core catches up in the verified entry. `CapKernel::enter`, in `kernel/verified/capability/operation.rs`, runs the dispatch and then, whenever the calling core is behind the flush epoch, has it acknowledge under the same lock hold, whichever core's unmap or revoke moved the epoch. Its ensures says the core has acknowledged the current epoch and that every entry of its TLB model is of a page that is mapped, which follows from the invariant that no page's stale epoch is later than the flush epoch: so the core returns to its thread holding no translation an unmap dropped, and a map that follows on it sees only what the tables say. A core that is not behind is not flushed, so a call costs a flush only once per epoch it missed. On the running kernel the IPIs an unmap records are made by the glue around the verified entry, `dispatch` in `kernel/src/capability.rs` with `owed` and `send` in `kernel/src/flush.rs`. It reads the flush epoch before the operation; when the operation moved it, once the lock is released the flush IPI goes to every other core that has loaded a space, its generation or its next tag moved from boot's, and is behind the epoch. Those cores include each core an unmap listed, since a core lists itself on a space only by loading it, which hands out a tag; a core that never loaded a space holds no tag and is sent nothing. The verified side records the IPIs as ghost `flush_ipis` and the glue sends them; the glue's mask is a superset of `flush_targets`, which costs a core that loaded only other spaces an extra flush and keeps the glue from reading a space's list of cores.

A free waits for the cores that have loaded a space and for the present IOMMUs, and for nothing else. `CapKernel::all_acknowledged`, in `kernel/verified/capability/kernel.rs`, asks a core for its acknowledgement only when `has_loaded` holds of its state, its generation or its next tag moved from boot's. A core that never loaded a space holds no entry of the model, which `lemma_loaded_a_space` proves from the invariant, so nothing is owed by it; and it could not pay, since it is sent no IPI and, running no thread, makes no entry of its own. The test is one verified function of the core's state, `CoreState::loaded_a_space`, which `has_acknowledged` runs for the free and `owed` in `kernel/src/flush.rs` runs for the IPI mask, so the cores a free waits for and the cores the glue interrupts are the same set, less the calling core, which `enter` has acknowledge. What an unmap promises follows it: the page it leaves stale is unacknowledged when a core has loaded a space or an IOMMU is present, `flush_awaited`, and on a kernel where neither holds nothing can hold a translation and the free goes ahead.

## Reasoning

A core may be spinning for the lock with IF clear, `design/one-lock-bounded-steps/`, and so cannot take an IPI; a holder that waited for it would deadlock. Returning `again` and letting the acknowledgement arrive on the target's own entry is the only shape that keeps the no-wait rule and keeps the state inside the kernel value, `design/one-kernel-instance/`.

The no-wait rule is about cores. An IOMMU takes no lock and no interrupt: it reads its command buffer whatever any core's IF says, so a core waiting on its completion word cannot deadlock against a core spinning for the lock. The wait is bounded by the IOMMU's command latency, not by another core's progress. Acknowledging on a later entry would need a second cited leaf to read the completion word and a ghost record of the epochs submitted to each IOMMU, so that a token could not claim an epoch the invalidate did not start at; waiting in `invalidate_iommu_all` needs neither, and the epoch acknowledged is the one `flush_iommu` read before the invalidate.

Keying the model by loaded space, and covering table pages, is what makes the token mean something for a retype of a table page as well as a frame. An acknowledge counter outside the kernel value was an earlier shape and was rejected because the proof could not see it.

## Alternatives rejected

- **Wait under the lock for the IPI.** Deadlocks against a waiter with interrupts off.
- **Flush only the current PCID.** Stale entries survive under other PCIDs and the acknowledgement proves nothing.
- **An acknowledge counter outside the kernel value.** Invisible to the invariant.
- **Acknowledge an IOMMU on a later entry.** Submit the invalidate, return, and read the completion word when retype next needs the epoch. It keeps the lock hold shorter by one command latency, at the cost of a second hardware item and ghost state tying the stored word to a submitted epoch.

## What this does not settle

- How long an IOMMU's completion wait holds the lock, which is unmeasured, and what a step does about an IOMMU that halts command processing and never stores. `submit_invalidate` relies on boot listing an IOMMU as present only once its command buffer runs and it reports INVALIDATE_IOMMU_ALL (IASup); an IOMMU that rejects the command halts its command processing and `submit_invalidate` spins.
- A device's own IOTLB. INVALIDATE_IOMMU_ALL empties the IOMMU's caches and not a device's address translation cache, so the token covers a device only while its device table entry leaves ATS off.
